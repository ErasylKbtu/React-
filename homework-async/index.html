Sequential vs Concurrent Execution

Sequential execution waits for each task before starting the next one. Concurrent execution starts all tasks together.

Why are the results different?

In sequential execution, each task waits until the previous task has finished. Because of this, the total time is approximately the sum of all task loading times.

In concurrent execution, all tasks start almost at the same time. The total time is therefore close to the time of the slowest task.

Execution Order

1. Call Stack: JavaScript first executes all synchronous code.

2. Microtask Queue: Promise callbacks and async/await continuations are executed after the Call Stack becomes empty.

3. Task Queue: setTimeout callbacks wait in the Task Queue.

4. Event Loop: The Event Loop moves callbacks to the Call Stack when JavaScript is ready to execute them.
