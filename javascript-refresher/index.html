Variables and data types

A student record, printed with its types, plus a look at null vs undefined and which values are primitive vs reference.


    

    
console

    

    

      
let vs const

      
let can be reassigned after declaration; const cannot be reassigned, though if it holds an object or array, the contents of that object/array can still be mutated — only the variable binding itself is locked.

      
typeof null

      
Returns "object". This is a long-standing bug baked into the language since its first version — null is not actually an object, but the check can never be fixed without breaking existing code.

      
Primitive types

      
string, number, boolean, null, undefined, bigint, and symbol. Everything else — objects, arrays, functions — is a reference type.

    

    
noticedArrays and plain objects both report typeof as "object" — you need Array.isArray() to actually tell them apart.

05
Values and references

  

    
copy = original doesn't copy an object — it copies the reference. Mutating copy mutates original too. Shallow spread fixes the top level but not nested objects.

    

      
      

    

    
console

    

    

      
Why does changing copy.score change original.score?

      
Objects are reference types. original and copy both point at the same location in memory — assignment copies the pointer, not the data.

      
Why does the spread copy still leak the nested address?

      
The spread operator only copies one level deep. The top-level keys are new, but address itself is still the same nested object reference shared by both copies — a proper fix needs a deep clone, e.g. structuredClone() or spreading each nested level by hand.

07
Functions as values

  

    
add and multiply passed into a calculate function as arguments — treating a function like any other value.

    

      
      

    

    
console

    

    

      
Can functions be stored in variables?

      
Yes — functions are first-class values in JavaScript, just like numbers or strings.

      
Can functions be passed to other functions?

      
Yes — a function taken as an argument (like operation here) is usually called a callback, or a higher-order function pattern when the outer function also returns one.

      
add vs add()

      
add is a reference to the function itself, which is what you pass around. add() actually invokes it and evaluates to its return value.

    

  






  
08
Scope

  

    
The same name, message, redeclared at the global, function, and block level, to see which one wins where. Also: what happens when var, let, and const declared inside a block are accessed from outside it.

    

      
      

    

    
console

    

    

      
Global scope

      
Declared outside any function or block; visible everywhere in the file (or module).

      
Function scope

      
A variable declared inside a function is only visible inside that function — var respects only this boundary, not block boundaries.

      
Block scope

      
A variable declared with let or const inside { } — an if, a loop, any braces — only exists inside those braces.

      
var vs let vs const

      
var is function-scoped and hoisted with an undefined placeholder; let and const are block-scoped and stay in a "temporal dead zone" until their line runs, which is why accessing them early throws instead of silently returning undefined.

Destructuring, spread and rest

  

    
Pulling values out of arrays and objects, building new copies with extra fields via spread, and a sum(...numbers) that accepts any number of arguments via rest.

    

      
      

    

    
console

    

    
Spread expands a collection out into individual elements — used when calling/building something. Rest does the opposite: it gathers many individual arguments back into a single array — used when defining something. Same three dots, opposite direction, and the position (inside a literal/call vs. inside a parameter list) is what tells them apart.
